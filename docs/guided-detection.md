# Guided detection internals

How `POST /api/analyze-guided` places tracks. The code is in `track_boundaries.py`.

- **Best-match alignment** (`track_boundaries.guided_by_alignment`, used by `/api/analyze-guided`): each Discogs length is matched to the music between two chosen gaps, so one wrong length no longer shifts later cuts and an unknown length simply costs nothing. Steps: `smooth_envelope` (310 ms rolling median, removes clicks/thumps) -> `gap_candidates` (strong: quiet runs below the span's 3rd percentile + 10 dB, >= 0.4 s, runs < 1 s apart merged, scored by length + contrast with the music +-8 s; weak: quietest 0.3 s per 5 s window for segues, penalised) -> `align_durations_to_gaps` (vectorised DP over n-1 candidates, minimising the sum of `log1p(((L-d)/sigma)^2)` with sigma = 3 s + 3 % per track, minus `GAP_STRENGTH_W` x gap strength, doubled at side changes; unknown d = no cost; < 5 s tracks infeasible; a very long capture keeps its `MAX_ALIGN_CANDIDATES` strongest candidates, which bounds memory and time) -> `onset_cut`: the next song's onset follows the candidate's *last* quiet run of >= `ONSET_LONG_QUIET_S` (a merged candidate can contain a soft intro's first notes or run-out thumps before a flip) where the smoothed level rises `ONSET_RISE_DB` above that run, refined on the raw envelope to a >= 50 ms sustained rise (a click is shorter). After a side flip (arm-up silence <= `ARM_UP_DB` before the first sound) `_after_needle_drop` skips the thump and lead-in crackle, looking no further than `MIN_ALIGNED_TRACK_S` before the next chosen gap. The next track starts `PRE_ROLL_S` (0.8) before the onset and the previous track ends exactly there (a gap shorter than `PRE_ROLL_S` + `POST_ROLL_S` is shared in proportion), except silence beyond `MAX_TAIL_S` (4 s) after the fade is dropped. The first track starts and the last ends `EDGE_PAD_S` into the lead-in / run-out. Cuts are contiguous, so `refine_cuts` only widens the outer edges. `expected` = the track's own length from its song's onset; `snapped` = a real gap was used. With no known length at all it runs `guided_without_lengths` (below).
- **Side flips:** `side_breaks` are the track counts before lettered Discogs side changes; the alignment counts such a boundary's gap strength twice, and the fallback gap/scale model (`boundaries_from_expected_durations`) anchors the sides on a >= 10 s silence near the expected change. Numeric-only positions do not imply a flip.
- **No lengths at all** (`guided_without_lengths`, response `model: "align-even"`, `method: "count"` so the UI draws no ghost markers): sides first. `find_side_changes` takes the (number of `side_breaks`) longest non-music stretches (1 s blocks whose p75 is `SIDE_QUIET_DB` 15 under the median block, runs < `SIDE_MERGE_S` 5 s apart merged, >= `SIDE_MIN_S` 10 s) as strong candidates, so `onset_cut` gives the usual tail cap and `_after_needle_drop` skips the thump and nothing is centred in run-out noise; fewer stretches than side changes are matched to the changes a proportional split puts nearest (the rest are placed by the alignment with the flip bonus). Inside each side span `align_durations_to_gaps` runs on the recording-wide candidate pool (the quiet floor needs the plentiful noise; a span of its own takes quiet music for the floor) against an even split with `sigma_frac` `EVEN_SIGMA_FRAC` (2.5: the prior only breaks ties) and `EVEN_MIN_TRACK_S` (30) as the shortest song. More than `MAX_EVEN_CANDIDATES` (3000) in one span (over about 4 h with no side found) falls back to the count ladder; this guards the result, while `MAX_ALIGN_CANDIDATES` bounds the memory. `GET /api/scan/{id}?side_changes=N` exposes `find_side_changes`. The `no lengths` scenario of `tests/e2e/real_records_eval.py` compares it with the count ladder.
- **Fallbacks, in order:** best-match alignment -> gap/scale model (all lengths known: leftover span split evenly into n-1 gaps, `MAX_GAP_S` = 8 s, else proportional scaling clamped 0.9-1.1) -> count-based detection. The gap/scale model clamps surplus cuts to the end of the music, so a track under `MIN_ALIGNED_TRACK_S` rejects its result; count-based detection then reports `matched: false` if it can't reach the count.
- All constants are module-level and were tuned on real records with `tests/e2e/real_records_eval.py` (needs local `records/` + `output/` mounted read-only, see its docstring; not part of the suite). Synthetic cases: `tests/test_best_match_splits.py`. Not yet measured on classical / segued records. With no lengths, a pause of 10 s or more inside a piece can be taken for a side change when the real flip is shorter.
